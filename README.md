# multitracker-search

Поддерживаемый форк [TMS — Torrents MultiSearch](https://github.com/Feverqwe/tSearch) (Feverqwe/tSearch, архивирован в 2022): браузерное расширение, которое ищет раздачи сразу на нескольких торрент-трекерах и собирает результаты в одну таблицу с фильтрами.

- Поиск по нескольким трекерам одновременно, фильтры по категории, размеру, дате, сидам и пирам, подсветка совпадений, сортировка по релевантности.
- Профили с собственными наборами трекеров.
- Главная страница с подборками (Кинопоиск, IMDb, GameGuru): клик по постеру запускает поиск.
- Поиск из адресной строки (ключевое слово `tms`) и из контекстного меню по выделенному тексту.

Расширение на Manifest V3, работает в Chrome 120+, Vivaldi и других Chromium-браузерах. В Chrome Web Store не публикуется.

### Вход, Cloudflare и значок «Войти»

Расширение отправляет запросы с куками браузера, поэтому вход на трекер и пройденная проверка Cloudflare действуют и для поиска. Логин и пароль расширение не хранит.

- Если трекер ответил 403/503 или показал форму входа, вместо «0» рядом с ним появляется значок «Войти». Откройте сайт по этой ссылке, войдите или пройдите проверку и повторите поиск.
- Cloudflare хранит отметку о пройденной проверке (`cf_clearance`) как «разделённую» (partitioned) куку, и браузер сам не кладёт её в запросы расширения. Расширение читает её через `chrome.cookies` и добавляет в заголовок Cookie правилом `declarativeNetRequest`, которое действует только на запросы самого расширения.
- У Rustorka своя капча на странице поиска `tracker.php`, привязанная к сессии сайта, поэтому «Войти» ведёт именно туда.
- Подборки IMDb иногда упираются в защиту от ботов: IMDb отвечает пустой страницей, и секция показывает ссылку на сайт. Достаточно один раз открыть imdb.com в браузере.
- «Кинопоиск: Избранное» требует входа на Кинопоиск.

## Установка

1. Соберите расширение (см. ниже) или возьмите готовую папку `dist/dist`.
2. Откройте `vivaldi://extensions` (или `chrome://extensions`) и включите режим разработчика.
3. «Загрузить распакованное» → папка `dist/dist`.
4. После пересборки нажмите «Обновить» у расширения.

В `manifest.json` прописан `key` оригинального расширения, поэтому ID расширения не меняется: профили, история и настройки сохраняются при обновлении, в том числе при переходе с версии 3.x (Manifest V2) на 4.x.

## Сборка

Нужен Node 18 (`.nvmrc`). Сборщик — webpack 4.

```bash
nvm use
npm ci
npm run release
```

Результат: распакованное расширение в `dist/dist/` и архив `dist/tms-<версия>.zip`.

- `npm run build` — сборка для разработки (с source map), `npm run watch` — пересборка при изменениях.
- `src/trackers.json` и `src/explorers.json` (версии встроенных трекеров и подборок) генерирует `npm run release`.

## Как устроено

- **Страницы расширения** (`index.html`, `popup.html`) — React + MobX State Tree. Поиск и загрузка подборок выполняются на странице поиска: она шлёт запросы к трекерам и показывает результаты.
- **Код трекеров и подборок** исполняется в изолированной sandbox-странице (`sandbox.html`, по iframe на модуль). Сетевые запросы он делает через страницу (`API_request`), которая проверяет адрес по списку `@connect` модуля.
- **Фон** — service worker (`src/background`): омнибокс, контекстное меню, значок, автообновление трекеров и подборок по `@downloadURL`, режим «через вкладку». В service worker нет `window` и DOM, а его состояние в памяти живёт, пока он не уснёт.
- **Режим «через вкладку»** (в редакторе профиля — «Включить поддержку прокси» у трекера): запрос выполняется в маленьком фоновом окне сайта трекера, как если бы его сделала сама страница сайта. Окно закрывается после запроса.
- **Правила `declarativeNetRequest`** (сессионные, действуют только на запросы расширения):
  - добавляют partitioned-куки Cloudflare в заголовок Cookie, по одному правилу на хост (`src/tools/partitionedCookies.js`);
  - убирают из ответов заголовки `Link: rel=preload` (их отдаёт, например, LimeTorrents), иначе браузер применял их к странице расширения (`src/tools/stripPreloadHeaders.js`).
- **Повтор запросов.** На некоторых сетях первое соединение с сайтом обрывается: HTTP/3 (QUIC) не проходит (`QUIC_NETWORK_IDLE_TIMEOUT`), и браузер переключается на TCP только со следующего запроса. Поэтому все сетевые запросы при сетевой ошибке повторяются до трёх раз (`src/tools/retryOnNetworkError.js`).

### Разрешения

| Разрешение | Зачем |
|---|---|
| `http://*/*`, `https://*/*` | запросы к трекерам и источникам подборок; набор трекеров настраивается, можно добавить свой |
| `storage`, `unlimitedStorage` | настройки, профили, история, код трекеров и кэш подборок с постерами |
| `cookies` | чтение partitioned-кук Cloudflare для сайта трекера |
| `declarativeNetRequestWithHostAccess` | подстановка этих кук и очистка заголовков preload в запросах расширения |
| `scripting` | режим «через вкладку» |
| `contextMenus` | поиск по выделенному тексту |

## Трекеры и подборки: как добавить или поправить

Трекер — файл `src/trackers/<id>.js` с заголовком userscript (`@name`, `@version`, `@connect`, `@trackerURL`, `@downloadURL`). Подборка главной страницы — файл `src/explorerModules/<id>.js` с таким же заголовком. Сборка копирует их как есть.

Большинство трекеров описаны декларативно через exKit (`"type": "kit"`, `"version": 3`): URL поиска плюс селекторы строк и полей с конвейером обработки (`getText`, `getProp`, `toInt`, `legacySizeFormat`...). Поведение можно дополнить хуками в `code.hooks`:

- `onBeforeRequest(session, options)`, `onAfterRequest(session, response)`, `onGetDoc(session, doc)`, `transform[поле](session, value, container)`;
- `onRequestError(session, err, options)` — вернуть ответ вместо ошибки. Например, MegaPeer отвечает 404, когда ничего не найдено, и хук превращает это в пустую выдачу.

Если нужна своя логика целиком, трекер может сам вызвать `API_request` и `API_event('search', ...)` — так сделан `thepiratebay.js`.

Важно:

- **При любом изменении трекера или подборки поднимайте `@version`** (и `version` в описании кода). Установленное расширение хранит код модулей у себя и без новой версии продолжит использовать старый.
- Удалённые трекеры перечислены в `src/tools/removedTrackerIds.js`: они автоматически убираются из кэша и профилей.
- Хорошая подсказка для актуальных селекторов — определения [Jackett](https://github.com/Jackett/Jackett/tree/master/src/Jackett.Common/Definitions).

## Конфиденциальность

Расширение не собирает статистику и ничего не отправляет разработчикам: Google Analytics из оригинала удалена. История запросов, профили и настройки хранятся в браузере (профили синхронизируются через `chrome.storage.sync`).

Запросы уходят только на сайты выбранных трекеров, в источники подборок и, если включена настройка «Получать описание поискового запроса из Google», в поиск Google (за карточкой с описанием фильма). Эту настройку можно выключить.

## Решение проблем

- **У трекера «Войти» вместо результатов** — см. раздел «Вход, Cloudflare и значок „Войти“».
- **Трекер иногда не отвечает с первого раза.** Обычно это обрыв первого соединения по QUIC; расширение повторяет запрос само. Если сеть систематически не пропускает HTTP/3, помогает отключить QUIC в браузере: `vivaldi://flags/#enable-quic` (или `chrome://flags/#enable-quic`) → Disabled.
- **Часть трекеров не открывается вообще** — проверьте DNS: корпоративные VPN-DNS не резолвят некоторые трекеры. Помогает DNS-over-HTTPS в настройках браузера.
- **В списке «Ошибки» у расширения старые записи.** Браузер хранит их и после обновления расширения, пока не нажать «Удалить все». Прежде чем разбирать ошибку, очистите список и повторите действие. Сообщения `Failed to load resource` о самих сетевых сбоях выводит браузер, расширение их не подавляет.
- **После правки трекера ничего не изменилось** — поднимите `@version` и пересоберите (см. выше).

## Разработка и проверка

- Трекеры со входом и за Cloudflare проверяются только в браузере, где выполнен вход.
- Остальное удобно проверять в отдельном экземпляре Chrome через [puppeteer-core](https://pptr.dev/) с временным профилем: `puppeteer.launch({pipe: true, enableExtensions: true, userDataDir})`, затем `browser.installExtension('<путь>/dist/dist')`. Обычный Chrome игнорирует флаг `--load-extension`, поэтому расширение ставится через CDP. Если провайдерский DNS не резолвит трекеры, включите DoH в профиле: в файл `Local State` профиля запишите `{"dns_over_https": {"mode": "secure", "templates": "https://cloudflare-dns.com/dns-query"}}`.
- Service worker расширения доступен как отдельная цель (`browser.waitForTarget(t => t.type() === 'service_worker')`), его консоль и `chrome.*` API проверяются через `target.worker()`.

## История изменений

### 4.0.0

- Переход на Manifest V3: фон работает как service worker, partitioned-куки Cloudflare передаются правилом `declarativeNetRequest`, режим «через вкладку» использует `chrome.scripting`.

- Ответы 403 со ссылкой «Войти» и отсутствие следующей страницы результатов не попадают в список ошибок расширения.
